# Bloom: free testing setup

**No payment has been made and no service is deployed by changing these files.** You must create the Free service in your own hosting account. This setup does not run automatic posts or live analytics.

## On the screen you already have

1. Leave the card/payment screen without submitting payment details.
2. Return to the Blueprint setup. If it displays old settings, reload the page or start a new Blueprint.
3. Choose repository **abc07552/Instagram-automation-**.
4. Choose branch **arena/d3fb70ad-instagram-automation**.
5. Keep Blueprint Path **render.yaml**. **Do not choose `render.persistent.yaml`**: that file is paid.
6. Name it **Bloom Free Test** and reload/retry the configuration preview if needed.
7. Confirm it shows **one Free web service**, no persistent disk, and no paid database or worker. Do not continue with Starter compute or any paid resource.
8. Set `META_APP_ID`, `META_APP_SECRET`, and `META_LOGIN_CONFIG_ID` **privately in the hosting dashboard**, not in chat, code, or screenshots. Owner password and encryption key are generated by the Blueprint.
9. Deploy only if you accept the host's terms and the displayed configuration is Free.

If Render still requests a card, it may be an account-verification requirement, even for free compute. There is no setting in this repository that bypasses provider verification. Stop if you do not want to enter a card. Never send card details here. Do not try to get past the prompt by changing to a paid plan.

## If you need to create a Web Service manually

Choose **New → Web Service**, select the same repository and branch, then use:

| Setting                      | Value                                 |
| ---------------------------- | ------------------------------------- |
| Name                         | Bloom Free Test                       |
| Runtime                      | Node                                  |
| Branch                       | `arena/d3fb70ad-instagram-automation` |
| Build command                | `npm ci --omit=dev && npm run build`  |
| Start command                | `npm start`                           |
| Instance type / compute plan | **Free**                              |
| Disk                         | **None**                              |
| Health check                 | `/healthz`                            |

Add these private environment settings:

| Key                    | Value                                                                              |
| ---------------------- | ---------------------------------------------------------------------------------- |
| `NODE_VERSION`         | `22.22.0`                                                                          |
| `NODE_ENV`             | `production`                                                                       |
| `STORAGE_MODE`         | `ephemeral`                                                                        |
| `DATABASE_PATH`        | `/tmp/bloom/bloom.sqlite`                                                          |
| `META_API_VERSION`     | `v26.0`                                                                            |
| `META_APP_ID`          | Your Meta App ID from App settings → Basic                                         |
| `META_APP_SECRET`      | Your app secret from that same page                                                |
| `META_LOGIN_CONFIG_ID` | The selected Unified Login Configuration ID                                        |
| `ADMIN_PASSWORD`       | A long, randomly generated private password for Bloom, not your Instagram password |
| `TOKEN_ENCRYPTION_KEY` | A separate randomly generated secret of at least 32 characters                     |

Keep the two generated secrets different. You can generate them with a trusted local password manager, or run `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` twice on your own computer. Do not choose example credentials or have someone post real credentials in chat. The manual path does not guarantee exemption from account verification.

## After the service is live

1. Open its actual HTTPS service address.
2. In Bloom, open the account menu and enter `ADMIN_PASSWORD` from your private hosting settings.
3. Copy the exact Redirect URL shown in Bloom and save it in Meta's Unified Login setup. Do not invent a hostname or use the GitHub Pages homepage.
4. Tap **Continue with Meta**, review the permissions, and sign in on Meta's official page.
5. Choose your Creator account when Bloom returns, then use **Verify access**.

This real Meta round trip has not been tested with your account. Local tests use a mocked provider. Your Meta app/tester roles, portfolio assignments, permissions, and access levels still apply.

## What can disappear?

The SQLite file is on temporary storage. Owner sessions, pending sign-in state, and saved Instagram connections can disappear when the instance sleeps, restarts, or redeploys. Sign in as owner and reconnect if that happens. Do not disable OAuth state or cookie protections to work around a lost session. Saved environment variables are separate from that file.

Loss of the local token does **not** revoke Meta's authorization. To revoke the app's access, use Disconnect while a token is available, or remove the integration in Meta's connected-app settings. Drafts remain browser-local, not on the backend.

Free services can sleep and have resource limits, so this is a connection test—not an always-on scheduler. Do not add keep-alive traffic to bypass host restrictions.

Provider references: https://render.com/docs/free, https://render.com/docs/your-first-deploy, and https://community.render.com/t/free-web-service-issue/18026. Availability, verification, and limits are controlled by the provider.
